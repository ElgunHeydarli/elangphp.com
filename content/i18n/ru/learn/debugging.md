# Поиск и исправление проблемы в Elang

Хороший процесс отладки сужает круг причин до изменения кода. Этот урок даёт повторяемую последовательность действий для проблем локальной настройки и HTTP-сбоев.

## Шаг 1: зафиксируйте сбой

Запишите команду или URL, метод, статус и ожидаемый результат. Адресная строка браузера отправляет GET. Для примера с JSON POST нужен HTTP-клиент или запрос fetch с правильным телом и Content-Type.

Меняйте по одному параметру за раз. Если одновременно обновить PHP, изменить URL базы данных и переписать маршрут, вы потеряете сведения о том, какое изменение повлияло на результат.

## Шаг 2: проверьте окружение

```bash
php -v
php elang doctor
php elang routes
```

Doctor проверяет требования, закрытое хранилище, конфигурацию ключа и подключение к базе данных без вывода учётных данных. Список маршрутов показывает, действительно ли приложение зарегистрировало используемые путь и метод.

## Шаг 3: прочитайте код статуса

- 404: проверьте путь, требования параметров и правило перенаправления веб-сервера.
- 405: проверьте HTTP-метод и заголовок Allow.
- 419: обновите форму и проверьте привязанный к сессии токен CSRF.
- 422: изучите ошибки полей в JSON-ответе.
- 429: подождите в течение Retry-After и проверьте частоту своих запросов.
- 500: изучите закрытый журнал сервера по идентификатору запроса из ответа.

Не считайте любой сбой проблемой базы данных. Каждый статус указывает на отдельный уровень.

## Шаг 4: изучите безопасный пример воспроизведения

Замените вызов внешнего API или сложный контроллер небольшим маршрутом, возвращающим известный массив. Если он работает, возвращайте следующую зависимость. Используйте временные данные при проверке запросов или форм.

Не включайте секреты в снимки экрана, публичные задачи и вставляемые трассировки стека. Сбой запроса можно описать без раскрытия реальных учётных данных.

## Шаг 5: проверьте исправление

Повторите исходный запрос. Проверьте успешный сценарий и тот сценарий ошибки, который вы намеревались обработать. Если меняли валидацию, проверьте как недопустимый, так и допустимый ввод. Если меняли маршрут, проверьте нужный и неподдерживаемый методы.

Для повторяющейся ошибки добавьте целевой автоматический тест. Затем запустите соответствующий тест и проверки фреймворка перед публикацией изменения.

## Практическое упражнение

Временно обратитесь к `/hello` методом POST, когда для него существует только маршрут GET. Убедитесь в ответе 405, прочитайте список маршрутов и определите правильный метод. Исправьте запрос, не меняя маршрут. Вы исправили вызывающую сторону, сохранив строгость поведения приложения.

Перейдите к [подготовке развёртывания](/learn/ship) и держите под рукой [справочник по устранению неполадок](/docs/v0.1/troubleshooting) для конкретных сообщений об ошибках.
